# oral-script — 口播稿写作

案板的核心创作流程：**选题 → 查证 → 口播稿**。本技能负责把选题卡变成能直接照着说的稿子。

## 什么时候用

- 用户说"帮我写个口播稿""写文案""写个脚本"
- 已有选题卡，要产出成稿
- 稿子写完要口语化改写、压时长

## 流程

### 1. 定钩子（前三秒）

口播第一句决定生死。钩子公式：

- 悬念式：「你有没有想过，为什么…」
- 反差式：「这道菜，厨师界吵了三十年」
- 故事式：「1791 年冬天，一个苏格兰人把鳕鱼倒进了…」

钩子要**具体**（有时间/地点/人物/数字），不要"大家好今天给大家讲个有趣的故事"。

### 2. 搭故事线

老饕+说书人结构（起-承-转-合）：

```markdown
## 起（15%）：钩子 + 一句话预告"这期讲什么、为什么值得听"
## 承（55%）：主体叙事
  - 按时间/因果推进，一个段落一件事
  - 细节要"可感"：颜色、声音、气味、价格、重量
## 转（20%）：冷知识/反转/冲突点——观众的"哇"时刻
## 合（10%）：收尾金句 + 一句"下期预告/互动提问"
```

### 3. 事实先行

动笔前先用 fact-check 技能核查核心事实（数字、年代、人名、地名），**稿子里出现的每个具体事实都必须是查过的**。写稿时把不确定的地方标 `[待查]`，成稿前清空。

### 4. 口语化改写

把书面语改成"说出口"的样子：

- 长句拆短句，一句一个意思
- 删掉"首先/其次/总而言之"，换成"话说回来""你猜怎么着"
- 数字要"人话"：「20 万吨」→「够全北京人吃一年」
- 多问句、多感叹，但别滥用

### 5. 字数与时长控制

- 中文口播语速约 **240-280 字/分钟**
- 3 分钟稿 ≈ 750-850 字；5 分钟稿 ≈ 1250-1400 字
- 超了先砍"承"的细节，别砍钩子和金句

## 输出格式

```markdown
# 口播稿：<标题>
> 时长预估：X 分钟（约 X 字）

（正文，按 起承转合 分节，含口语化过渡语）

## 金句（可直接做标题/封面）
1. …
2. …

## 待查项
- [ ] （成稿前必须清空）
```

## 坑（血的教训）

- **别堆书面语**：稿子是"念"的不是"读"的，写完后出声读一遍，拗口就改
- **别贪多**：一期只讲一件事，信息超载是口播大忌
- **别用 AI 味句式**：「值得注意的是」「综上所述」「首先，让我们」一律删

## 验证

- [ ] 前三秒有钩子（具体、有画面）
- [ ] 所有具体事实已过 fact-check（无 [待查] 残留）
- [ ] 出声朗读一遍：无拗口句、无书面语残留
- [ ] 字数符合目标时长（±10%）
