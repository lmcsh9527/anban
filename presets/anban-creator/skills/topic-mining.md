# topic-mining — 选题挖掘

案板的核心资产之一：**好内容从好选题开始**。本技能把零散灵感变成可落地的选题卡。

## 什么时候用

- 用户说"没选题了"、"帮我找个选题"、"最近做什么内容好"
- 开始新一期创作前，需要从素材池里捞选题
- 评估某个灵感是否值得做成视频

## 流程

### 1. 建矿（素材入库）

把素材按「母链」归类——同一主题的系列内容就是一条矿脉：

- 领域（美食/历史/博物）→ 子主题（如"鳕鱼战争""中岛成子案""辣椒传播史"）
- 每个灵感记 3 件事：**钩子**（一句话为什么有人想看）、**素材源**（书/文章/播客/亲身经历）、**关联母链**（属于哪条矿脉，能否续作）

### 2. 挖矿（选题生成）

对每条矿脉，按四个角度挖选题：

| 角度 | 问法 |
|---|---|
| 人物 | 这个主题里有没有"人"的故事？（老饕、厨师、历史人物、发明者） |
| 冲突 | 有没有争议、反转、冷知识？（"这个你绝对想不到"） |
| 溯源 | 这东西从哪来？怎么传遍世界的？（食物自然史视角） |
| 对比 | 中 vs 西、古 vs 今、贵 vs 贱？ |

每个角度至少产出一个候选选题，写成一行的**选题钩子**。

### 3. 选题卡（一次一个）

选题卡固定格式：

```markdown
# 选题：<一句话标题>
- 钩子：<为什么有人点进来，20 字内>
- 受众：<谁会看，他在什么场景下看>
- 角度：<人物/冲突/溯源/对比>
- 母链：<所属系列>
- 可用素材：<1-3 条，具体到来源>
- 可查证性：<这个题目能不能找到可靠资料？> ← 查不到就先标记，别硬做
```

### 4. 验证（用 web_search）

对候选选题做三查：

1. **热度查**：有没有人在搜/在看相关话题（搜索结果数量、近期讨论）
2. **竞争查**：头部内容怎么做的？你的角度有什么不同？
3. **事实查**：核心事实能否找到 2 个以上独立来源？（配合 fact-check 技能）

三项都过的选题进入待做队列，输出选题卡清单（一次 3-5 个）。

## 坑（血的教训）

- **别做查不到资料的题**：博物/历史向最忌编造，可查证性是选题的硬门槛
- **别只做一次性选题**：优先选能续作的母链（一个母链可挖 5-10 期）
- **钩子 ≠ 标题**：钩子是内部用的"一句话卖点"，标题到发布时再优化

## 验证

- [ ] 输出的是选题卡（含钩子/受众/角度/母链/素材/可查证性），不是空泛标题
- [ ] 每张卡都跑过 web_search 三查
- [ ] 至少 1 个选题属于已有母链（可续作）
